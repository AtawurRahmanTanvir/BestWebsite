13. MOBILE APP PRESENTATION — MAJOR ARCHITECTURAL CHANGE
==================================================

The previous approach of simply showing the entire original HTML application inside a mobile device frame is NOT acceptable.

The problem is:

The original application was designed primarily for its own full-screen desktop composition.

Even if it looks good at PC size, forcing the entire application into a small mobile mockup can cause:
- poor positioning
- awkward scaling
- broken composition
- unreadable UI
- incorrect proportions
- visually weak screenshots
- excessive empty space

Therefore:

DO NOT show the entire application as a miniature “phone screenshot” on mobile.

Instead, create a responsive presentation layer around the real application.

When a section needs to demonstrate something specific from the real app:

1. Navigate the real app to the required screen.
2. Show ONLY the relevant portion of that real app.
3. Use a controlled presentation viewport.
4. Crop/mask the unused application regions.
5. Scale the useful region intelligently.
6. Position the relevant control or screen area precisely.
7. Preserve the real application's actual DOM/UI.
8. Never fabricate a replacement UI.

For example:

If a section is explaining:
- Generator input
- Engine switches
- Library records
- One Touch state
- Settings tree
- Check Route
- Log Engine

then show the relevant part of the actual application required to explain that concept.

Do NOT force the entire application into the frame.

The website should effectively say:

“Here is the real part of the application relevant to this story.”

That is much more powerful than showing a tiny full application.
