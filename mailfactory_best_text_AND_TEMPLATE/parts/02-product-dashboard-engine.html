Product core
Architecture

One binary,
six surfaces

The six screens are not separate apps stitched together. They share one shell, one navigation model and one local store. Switching between them does not reload anything — the app swaps the active screen in place, which is exactly what this website does to the embedded copy as you scroll.

A

Shared shell

A single application root holds every screen; only one is active at a time.

B

No reload navigation

Moving between Engine, Generator and One Touch is a client-side screen switch.

C

Local store

The Library reads from device storage, so results survive between sessions.

D

Protected surfaces

Dashboard and Settings are treated as protected screens inside the app shell.

Engine

“Powerful automation engines.” Six of them, each independently switchable, plus the diagnostic tools that sit alongside them. Disabled engines are skipped by Optimize System and will not run in the background.

Interactive — toggle the board

Six engines.
You decide which run.

Switch any engine off below and watch the environment respond — the corresponding node powers down, its spoke dims and the hub loses intensity. This mirrors the app's own System Settings screen, where each engine has a real ON/OFF state.

Engine array / 3D Metallic · orbital

Check Route

Reports Route Status, Latency, Route and Last Checked. Before a check has been run the fields read “—” and Last Checked reads “Never”.
